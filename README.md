# Лекало — цифровой дизайнер презентаций

Сервис принимает корпоративный шаблон `.pptx` и бриф. Шаблон он разбирает на дизайн-систему: палитру, гарнитуры, шкалу кеглей, сетку, холсты и собственные композиции шаблона. По брифу пишет сценарий и тексты, затем собирает **три варианта** колоды в стиле шаблона:

- **A — классический:** максимально близко к шаблону, сбалансированная плотность;
- **B — визуальный:** меньше текста, больше крупных цифр, диаграмм, иконок и иллюстраций;
- **C — компактный:** плотнее, таблицы и сравнения, меньше слайдов.

Каждый слайд проходит встроенный аудит: 26 детерминированных проверок и 11 контекстных через VLM. Пользователь сам выбирает, какие замечания исправить. Экспорт — нативный PPTX (тексты, таблицы и диаграммы редактируются), PDF и HTML.

| | |
|---|---|
| Время на три колоды | 25–80 с без иллюстраций, ~2 мин с иллюстрациями (лимит ТЗ — 5 мин) |
| Объём | 10–15 слайдов в каждом варианте или число, заданное пользователем. Длительность выступления задаёт объём и текст спикера к каждому слайду |
| Входные данные | бриф + приложенные материалы (txt, md, pdf, docx, pptx): README, документация, отчёты, старая презентация |
| Шаблоны | любые `.pptx` / `.potx`, в том числе незнакомые и растровые (слайды-картинки из Figma/Canva) |
| Модели | Qwen3.6-35B-A3B (Apache 2.0) — текст и VLM; gpt-oss-20b (Apache 2.0) — запасная; Kandinsky через GigaChat — иллюстрации |
| Интерфейс | браузер на десктопе (Chrome, Firefox, Safari, Яндекс Браузер) и мини-приложение ВКонтакте |

# Часть I. Развёртывание и использование

## 1. Что понадобится

| Что | Зачем | Обязательно |
|---|---|---|
| Docker с Compose **или** Python 3.12 + Node 20 + LibreOffice | запуск сервиса | да |
| `LLM_API_KEY`, `LLM_FOLDER_ID` | доступ к Qwen3.6-35B-A3B и gpt-oss-20b (Yandex Cloud AI Studio, OpenAI-совместимый API) | **да**, без них генерация не запустится |
| `GIGACHAT_AUTH_KEY` | иллюстрации (Kandinsky через GigaChat) | нет, без ключа колоды собираются без картинок |
| Шаблон `.pptx` или `.potx` | дизайн-система для колоды | да, загружается из интерфейса |

**Ресурсы.** Своего инференса сервис не запускает: модели вызываются по API, GPU не нужен. На диске понадобится место под профили шаблонов, рендеры слайдов и кэш картинок: порядка десятков мегабайт на прогон.

**Куда смотреть в браузере.** Интерфейс рассчитан на десктоп. Веб-интерфейс проверяется в актуальной и предыдущей версиях Chrome, Firefox, Safari и Яндекс Браузера на macOS и Windows.

**Как получить ключи.**
- *Yandex Cloud AI Studio:* создайте сервисный аккаунт и API-ключ в консоли Yandex Cloud, `LLM_FOLDER_ID` — идентификатор каталога, в котором включён доступ к моделям. Имена моделей в `config.yaml` подставляют его вместо `{folder}`.
- *GigaChat:* [developers.sber.ru/studio](https://developers.sber.ru/studio). Нужен «ключ авторизации» (base64 от `client_id:client_secret`) и область доступа `GIGACHAT_API_PERS` для личного тарифа.

## 2. Развёртывание

### 2.1. Docker (рекомендуется)

```bash
git clone https://github.com/RealityFlex/LCT_pres lekalo && cd lekalo
cp .env.example .env         # впишите LLM_API_KEY, LLM_FOLDER_ID, при желании GIGACHAT_AUTH_KEY
docker compose up --build    # интерфейс: http://localhost:8000
```

Что происходит при сборке (`Dockerfile`):
1. Первый этап на Node 20 собирает фронтенд в `frontend/dist`.
2. Второй этап на Python 3.12 ставит LibreOffice (рендер PPTX→PDF), `fontconfig` и базовые кириллические шрифты, затем зависимости из `backend/requirements.txt`.
3. В образ копируются `config.yaml`, `examples/`, `backend/` и собранный фронтенд.
4. Контейнер слушает порт 8000, отвечает на `GET /api/health` (проверка здоровья каждые 30 с) и перезапускается сам (`restart: unless-stopped`).

Каталог `./data` монтируется в контейнер как `/app/data`: профили шаблонов, проекты, кэш картинок и шрифтов переживают перезапуск.

Остановить: `docker compose down`. Обновить после `git pull`: `docker compose up --build -d`.

### 2.2. Локально (Windows / Linux / macOS)

Нужны Python 3.12, Node 20 и LibreOffice (команда `soffice`).

```bash
pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
cp .env.example .env         # впишите ключи
python -m uvicorn app.api.main:app --app-dir backend --port 8000
```

Интерфейс откроется на http://localhost:8000: FastAPI раздаёт собранный фронтенд и API с одного порта.

Рекомендуется виртуальное окружение (`python -m venv .venv`). Версии зависимостей закреплены в `backend/requirements.txt` — это те версии, на которых проверен пайплайн.

**Где искать LibreOffice.** Сначала `SOFFICE_PATH` из `.env`, затем `render.soffice_path` из `config.yaml`, затем `soffice` и `libreoffice` в `PATH`, затем стандартные каталоги установки:
- Windows: `C:\Program Files\LibreOffice\program\soffice.exe`;
- Linux: `/usr/bin/soffice`;
- macOS: `/Applications/LibreOffice.app/Contents/MacOS/soffice`.

Если LibreOffice установлен в другое место, задайте `SOFFICE_PATH` в `.env`.

### 2.3. Режим разработки фронтенда

```bash
python -m uvicorn app.api.main:app --app-dir backend --port 8000   # бэкенд
npm --prefix frontend run dev                                       # http://localhost:5173
```

Vite проксирует `/api` на `127.0.0.1:8000`. Проверка типов: `npm --prefix frontend run typecheck`.

### 2.4. Переменные окружения

Секреты хранятся только в `.env` (он в `.gitignore`). Шаблон — `.env.example`.

| Переменная | Назначение |
|---|---|
| `LLM_API_KEY` | ключ API Yandex Cloud AI Studio. Обязательна |
| `LLM_FOLDER_ID` | идентификатор каталога Yandex Cloud, подставляется в имена моделей. Обязательна для Yandex Cloud |
| `LLM_BASE_URL` | необязательно: переопределяет `llm.base_url` из `config.yaml` (свой vLLM или другой OpenAI-совместимый эндпоинт) |
| `GIGACHAT_AUTH_KEY` | ключ авторизации GigaChat для иллюстраций |
| `GIGACHAT_SCOPE` | область GigaChat, по умолчанию `GIGACHAT_API_PERS` |
| `DATA_DIR` | каталог данных, по умолчанию `./data` (в Docker — `/app/data`) |
| `SOFFICE_PATH` | путь к `soffice` |
| `APP_CONFIG` | путь к другому файлу конфигурации вместо `config.yaml` |

### 2.5. Замечания по эксплуатации

- **Нет аутентификации.** API открыт, CORS разрешён для всех источников. Для доступа из сети ставьте сервис за обратный прокси с авторизацией и не выставляйте порт 8000 в открытый интернет.
- **Прогресс идёт через SSE** (`/api/jobs/{id}/events`). Если сервис стоит за nginx, отключите буферизацию для этого пути (`proxy_buffering off`), иначе индикатор прогресса будет обновляться рывками.
- **Состояние задач хранится в памяти процесса и на диске.** Если сервер перезапущен посреди генерации, задача помечается ошибкой и запускается заново из интерфейса.
- **Один процесс uvicorn.** Задачи живут в памяти процесса, поэтому не запускайте несколько воркеров на одном каталоге `data`.

## 3. Первый запуск и проверка

1. Проверьте, что сервис видит модели и LibreOffice:

   ```bash
   curl http://localhost:8000/api/health
   ```

   Ответ содержит:
   - `llm.configured` — `true`, если задан `LLM_API_KEY`;
   - `llm.model` и `llm.vision` — используемые модели;
   - `images.enabled` — `true`, если есть ключ GigaChat;
   - `soffice` — путь к LibreOffice или текст ошибки;
   - `variants` и `deadline_s` — активные варианты вёрстки и общий дедлайн прогона.

2. Откройте http://localhost:8000, перейдите в «Шаблоны» и загрузите любой `.pptx`. Разбор занимает от 20 секунд до двух минут в зависимости от числа слайдов и шрифтов (на разобранных шаблонах — 20–107 с). Повторная загрузка того же файла мгновенна: профиль кэшируется по sha256.
3. Нажмите «Новая презентация», выберите шаблон, нажмите одну из кнопок «Заполнить примером» и запустите генерацию. Через 1–2 минуты появятся три варианта.

## 4. Как пользоваться: веб-интерфейс

### 4.1. Шаблоны

Раздел «Шаблоны» — библиотека разобранных шаблонов.

- **Загрузка.** Перетащите `.pptx` или `.potx` в область загрузки. Можно грузить и на шаге 1 мастера новой презентации.
- **Разбор.** Сервис извлекает палитру, гарнитуры, шкалу кеглей, поля, «холсты» (слайды без контента), образцы композиций и нарратив шаблона. Этап и прогресс разбора виден в области загрузки.
- **Просмотр.** В карточке шаблона: палитра, типографика, поля, список холстов с превью, слайды исходника с пометками (служебные слайды, группы карточек), формат повествования.
- **Удаление.** Убирает профиль шаблона; готовые проекты остаются.

Подходят любые шаблоны. Шрифты берутся из файла, недостающие подкачиваются из Google Fonts. Растровые шаблоны (слайды-картинки из Figma или Canva) восстанавливаются приближённо, см. [ограничения](#11-ограничения).

### 4.2. Новая презентация

Мастер из двух шагов; справа сводка и кнопка запуска.

**Шаг 1. Шаблон.** Выберите карточку или загрузите новый файл.

**Шаг 2. Бриф.**

| Поле | Что писать | Влияние |
|---|---|---|
| О чём презентация | тема, 3–140 знаков. Обязательное поле | заголовок колоды и её сюжет |
| Назначение | проект / продукт / фича / инициатива / обучение / другое | сюжетная арка: например, для фичи «проблема → как работает → метрики → план запуска → риски» |
| Аудитория | кто будет смотреть | тон и глубина изложения |
| Данные и факты | цифры, результаты, сроки, риски | **единственный источник цифр и фактов.** Числа, которых здесь нет, на слайды не попадают. Ряд значений даёт диаграмму, отдельные числа — крупные цифры |
| Материалы | файлы txt, md, pdf, docx, pptx и другие текстовые (csv, json, yaml, html, rst); до 10 файлов за раз | их текст (до 20 тыс. знаков на файл и 30 тыс. в сумме) становится источником фактов наравне с полем выше |
| Длительность выступления | не важно / 5 / 7 / 10 / 15 / 20 мин | объём колоды (~1,5 слайда в минуту, в пределах 10–15) и объём текста спикера (130 слов в минуту) |
| Иллюстрации | где уместно / обязательно / без картинок | «обязательно» — 2–3 слайда с иллюстрацией; без ключа GigaChat картинок не будет в любом режиме |
| Количество слайдов | автоматически / задать (5–20) | «автоматически» — 10–15 по объёму брифа |
| Автор | имя или команда | попадает на титульный слайд |

Черновик брифа сохраняется в браузере (`localStorage`), поэтому не пропадёт при обновлении страницы.

Запуск: кнопка «Сгенерировать 3 варианта», `Enter` в поле темы или `Ctrl` + `Enter`.

**Советы, как получить лучший результат.**
- Пишите в «Данные и факты» конкретные числа с единицами и периодами: «время сборки 4,5 → 1,5 часа», «бюджет 48 млн руб.». Без цифр презентация будет качественной: карточки, процессы, сравнения.
- Чтобы получить график, дайте ряд значений: «янв 4,5; фев 4,2; мар 3,1…».
- Если тема шире брифа, приложите README, отчёт или старую презентацию.
- Задайте длительность выступления, если презентацию будут читать вслух: вы получите и нужный объём, и текст спикера.

Примеры брифов лежат в `examples/`. Их же предлагает кнопка «Заполнить примером».

### 4.3. Ход генерации

После запуска открывается экран прогресса. Этапы:

| Этап | Что происходит |
|---|---|
| Сценарий колоды | модель пишет структуру, заголовки и тексты. Числа не из брифа убираются до вёрстки |
| Иллюстрации | (необязательный) генерация картинок для слайдов-иллюстраций |
| Вёрстка трёх вариантов | раскладка по сетке и стилю шаблона; тексты, не влезшие в макет, сокращаются |
| Сборка и рендер | PPTX с нативными объектами и превью слайдов |
| Аудит | детерминированные проверки и VLM-ревью каждого слайда |
| Экспорт | PPTX, PDF, HTML |

На экране видны найденный сценарий и заготовки вариантов по мере готовности. Прогон держится в пределах 300 с: при нехватке времени контекстный аудит сокращается, колоды не теряются.

### 4.4. Проект: просмотр, аудит, экспорт

Когда генерация завершена, открывается страница проекта.

- **Вкладки A / B / C.** Три варианта вёрстки одного и того же контента.
- **Лента слайдов и просмотр.** Слева миниатюры, в центре крупный слайд. Навигация: `←` / `→` или `PageUp` / `PageDown`.
- **Заметки спикера.** Кнопка «Заметки» под слайдом показывает текст спикера; он же записывается в заметки PPTX.
- **Сравнить варианты.** Сетка из трёх вариантов рядом, клик открывает слайд.
- **Показ.** Полноэкранный режим: клавиша `F` или кнопка «Показ». Листать `←` / `→`, пробел и `Enter`, выход — `Esc`.
- **Аудит.** См. следующий раздел.
- **Меню «Ещё».**
  - «Тот же контент на другом шаблоне» — сценарий и тексты сохраняются, меняется только дизайн-система. Не тратит время на новый сценарий.
  - «Сгенерировать заново» — новый сценарий по тому же брифу.
  - «Поделиться ссылкой» — ссылка на проект; в мини-приложении ВКонтакте открывает диалог «поделиться».
  - «Удалить проект» — недоступно, пока идёт генерация.
- **Скачивание.** Форматы PPTX, PDF и HTML для каждого варианта отдельно.

**Форматы экспорта.**
- **PPTX** — нативные объекты: тексты, таблицы и диаграммы редактируются в PowerPoint, макеты берутся из шаблона. Слайды не сохраняются растровой картинкой.
- **PDF** — рендер LibreOffice.
- **HTML** — один файл со встроенным просмотрщиком: векторные SVG-страницы, навигация клавишами `←` / `→`, `F` — показ на весь экран, `Esc` — выход. Текст слайдов доступен экранным дикторам.

### 4.5. Аудит и исправления

Панель «Аудит слайдов» показывает замечания по слайдам; при наведении зона замечания подсвечивается на превью.

- **Фильтры:** по типу — «Все», «Оформление» (детерминированные проверки), «Смысл» (контекстные, через модель) — и по важности: ошибка, предупреждение, совет.
- **Замечания с пометкой «исправимо»** можно отметить флажком. «Выбрать исправимые» отмечает все сразу.
- **«Исправить выбранные»** применяет исправления, пересобирает вариант и проверяет заново. Детерминированный аудит повторяется целиком, контекстный — только по изменённым слайдам. Каждое исправление повышает номер ревизии.
- Часть замечаний исправить автоматически нельзя (например, слабая логика перехода). Они показываются без флажка.

Каталог всех 37 проверок и способов исправления — в [docs/AUDIT.md](docs/AUDIT.md).

## 5. Командная строка

Командная строка запускает тот же пайплайн без веб-интерфейса. Так удобно проверять воспроизводимость и гонять пакеты.

```bash
cd backend

# разбор шаблона → data/templates/<id>/profile.json
python -m app.cli parse ../path/template.pptx

# полный прогон: бриф → три варианта
python -m app.cli generate --template ../path/template.pptx --brief ../examples/brief_feature.yaml

# по id уже разобранного шаблона
python -m app.cli generate --template <id> --brief ../examples/brief_sklad.yaml

# без планировщика: готовая контент-модель
python -m app.cli generate --template <id> --content tests/fixtures/demo_content.json

# без ключей: разбор без VLM
python -m app.cli parse ../path/template.pptx --no-llm
```

Параметры:

| Команда | Параметр | Смысл |
|---|---|---|
| `parse` | `template` | путь к `.pptx` |
| | `--force` | разобрать заново, игнорируя кэш |
| | `--no-llm` | без VLM-описания стиля (профиль остаётся полным) |
| `generate` | `--template` | путь к `.pptx` или id разобранного шаблона |
| | `--brief` | YAML-файл брифа |
| | `--topic`, `--purpose`, `--audience`, `--details`, `--slides` | бриф прямо в командной строке вместо файла |
| | `--content` | готовая контент-модель JSON: планирование пропускается |
| | `--no-llm` | не использовать VLM при разборе шаблона |

**Формат брифа** (YAML, поля модели `Brief`):

```yaml
topic: Умные напоминания в мобильном банке   # обязательное
purpose: фича                                # фича | продукт | проект | инициатива | обучение | другое
audience: продуктовая команда
details: |                                   # единственный источник цифр
  A/B-тест на 120 тыс. пользователей, 6 недель.
  Просрочки снизились с 7,8% до 5,1%.
slide_count: null                            # число слайдов или null — автоматически (10–15)
duration_min: 10                             # длительность выступления, мин
author: ""
language: ru
images: auto                                 # auto | on | off
```

Поля `title_hint` в примерах — подпись кнопки «Заполнить примером» в интерфейсе, на генерацию они не влияют.

Каждый прогон пишет результат в `data/jobs/<id>/` (см. [раздел 8](#8-что-остаётся-на-диске-и-воспроизводимость)), а в консоль печатает этапы со временем и итоговую сводку: варианты, число слайдов, число замечаний, использованные версии скиллов, статистику вызовов модели.

## 6. HTTP API

Интерфейс общается с сервисом по HTTP; те же вызовы доступны любому клиенту. Интерактивная документация FastAPI — `http://localhost:8000/docs`.

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | состояние: ключи, модели, LibreOffice, варианты |
| `GET /api/stats` | число шаблонов и проектов, среднее время прогона |
| `GET /api/templates` | список разобранных шаблонов |
| `POST /api/templates` | загрузка `.pptx`/`.potx` (`multipart`, поля `file` и необязательное `force`). Ответ: `{id, status}`, где статус `ready` или `parsing` |
| `GET /api/templates/{id}/status` | прогресс разбора: `parsing` / `ready` / `error` |
| `GET /api/templates/{id}` | полный профиль: палитра, типографика, холсты, слайды |
| `DELETE /api/templates/{id}` | удалить шаблон |
| `GET /api/templates/{id}/slide/{n}.png` | превью слайда шаблона; `?w=` — миниатюра WebP |
| `GET /api/templates/{id}/canvas/{cid}.png` | превью холста |
| `POST /api/materials` | текст из файлов (`multipart`, поле `files`, до 10 файлов) |
| `POST /api/jobs` | запуск генерации: `{template_id, brief, materials[]}`. Ответ: `{id}` |
| `GET /api/jobs` | список проектов |
| `GET /api/jobs/{id}` | состояние задачи: этапы, варианты, статистика |
| `GET /api/jobs/{id}/events` | поток прогресса (SSE) |
| `GET /api/jobs/{id}/variants/{A\|B\|C}` | слайды варианта и отчёт аудита |
| `GET /api/jobs/{id}/variants/{vid}/slide/{n}.png` | превью слайда; `?w=` — миниатюра |
| `POST /api/jobs/{id}/variants/{vid}/fix` | применить исправления: `{issue_ids: [...]}` |
| `GET /api/jobs/{id}/variants/{vid}/download/{pptx\|pdf\|html}` | скачать файл; `?inline=true` — открыть в браузере |
| `GET /api/jobs/{id}/content` | контент-модель (сценарий) |
| `POST /api/jobs/{id}/rerun` | тот же бриф на другом шаблоне: `{template_id, reuse_content}` |
| `DELETE /api/jobs/{id}` | удалить проект (409, пока идёт генерация) |
| `GET /api/examples` | примеры брифов из `examples/` |
| `GET /api/skills` | скиллы: версии, активная версия, описание |
| `GET /api/audit/checks` | каталог проверок аудита |

**Пример: от шаблона до файла.**

```bash
# 1. загрузить шаблон
curl -F file=@template.pptx http://localhost:8000/api/templates
# {"id":"156543731f0b53b9","status":"parsing"}

# 2. дождаться разбора
curl http://localhost:8000/api/templates/156543731f0b53b9/status

# 3. запустить генерацию
curl -X POST http://localhost:8000/api/jobs -H "Content-Type: application/json" -d '{
  "template_id": "156543731f0b53b9",
  "brief": {"topic": "Умные напоминания в мобильном банке", "purpose": "фича",
            "details": "Просрочки снизились с 7,8% до 5,1%."}
}'
# {"id":"20260929-101500-a1b2c3"}

# 4. следить за прогрессом (SSE) или опрашивать состояние
curl -N http://localhost:8000/api/jobs/20260929-101500-a1b2c3/events
curl http://localhost:8000/api/jobs/20260929-101500-a1b2c3

# 5. забрать результат
curl -OJ "http://localhost:8000/api/jobs/20260929-101500-a1b2c3/variants/A/download/pptx"
```

## 7. Настройка

Всё, что влияет на результат, живёт в [`config.yaml`](config.yaml). Изменения подхватываются при перезапуске сервиса.

| Раздел | Что настраивается |
|---|---|
| `llm` | провайдер, `base_url`, модели `text_model` / `vision_model` / `fallback_model` (в именах `{folder}` заменяется на `LLM_FOLDER_ID`), `temperature`, `timeout_s`, `max_concurrency`, `disable_thinking` |
| `images` | `provider` (`gigachat` или `none`), `model`, `max_per_deck` (максимум иллюстраций на колоду), `timeout_s` |
| `render` | `soffice_path`, `max_parallel` (одновременных рендеров), `preview_dpi` |
| `pipeline` | `default_slide_count`, `min_slides`, `max_slides`, `deadline_s` (общий дедлайн прогона, 300 с), `contextual_audit` (`false` отключает VLM-аудит) |
| `variants` | описание трёх вариантов: `id`, `name`, `strategy` (`faithful` / `visual` / `dense`), `description` |
| `audit` | пороги проверок: 6 буллетов, 15 слов в пункте, таблица 7×5, 5 серий, заполненность ¼–¾, контраст 4,5:1, две гарнитуры |
| `skills` | активная версия каждого скилла (промпта): файлы `backend/skills/<имя>/<версия>.yaml` |

**Типичные сценарии.**
- *Свой инференс вместо облака:* укажите `llm.base_url` (или `LLM_BASE_URL`) и имена моделей своего OpenAI-совместимого сервера (vLLM, инференс VK). Код менять не нужно.
- *Без иллюстраций:* `images.provider: none` или не задавайте `GIGACHAT_AUTH_KEY`.
- *Быстрее и дешевле:* `pipeline.contextual_audit: false` пропускает VLM-проверки слайдов, детерминированный аудит остаётся.
- *Переключить версию промпта:* смените `skills.<имя>` на другую версию из `backend/skills/<имя>/`. Промпты не правятся на месте: изменение — это новый файл версии.

## 8. Что остаётся на диске и воспроизводимость

Каталог данных (`data/`, в Docker — `/app/data`) целиком создаётся сервисом:

```
data/
  templates/<sha256[:16]>/     разобранные шаблоны
    template.pptx              исходный файл
    profile.json               дизайн-система: палитра, типографика, холсты, паттерны
    preview/, canvases/        превью слайдов и холстов
  jobs/<дата-время-id>/        один проект = один прогон
    job.json                   состояние: бриф, этапы, варианты, версии скиллов, статистика
    content.json               сценарий (контент-модель)
    llm_trace.jsonl            все вызовы моделей: скилл@версия, промпты, ответ, время, токены
    A/ B/ C/                   по варианту:
      plan.json                какой рецепт и холст применены к каждому слайду
      layouts.json             промежуточное представление вёрстки
      audit.json               отчёт аудита
      deck_<вариант>.pptx / .pdf / <вариант>.html
      slides/slide-NNN.png     превью слайдов
  cache/                       кэш картинок, шрифтов, временных файлов
```

**Что воспроизводимо, а что нет.**
- Разбор шаблона, вёрстка, сборка и детерминированный аудит не используют модели и дают одинаковый результат на одинаковых входных данных.
- Текст сценария и контекстный аудит зависят от модели и на повторных запусках могут различаться.
- Чтобы повторить сборку точно, подайте сохранённый `content.json`: `python -m app.cli generate --template <id> --content data/jobs/<id>/content.json`. Сценарий пропускается, вёрстка и аудит выполняются заново.
- Версии зависимостей закреплены в `backend/requirements.txt`, конфигурация — в `config.yaml`, промпты — в версионируемых файлах скиллов. В `job.json` и `llm_trace.jsonl` каждого прогона записаны имя, версия и хэш использованного промпта.

## 10. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `LLM_API_KEY не задан (.env)` | нет `.env` или ключа. Скопируйте `.env.example` в `.env` и заполните. В Docker после правки `.env` перезапустите контейнер |
| `модель недоступна: …` | ключ неверный, нет доступа к модели в каталоге, сеть или лимиты. Проверьте `LLM_FOLDER_ID` и включён ли доступ к моделям в Yandex Cloud. Сервис сам пробует запасную модель |
| `LibreOffice (soffice) не найден. Укажите SOFFICE_PATH.` | установите LibreOffice или задайте `SOFFICE_PATH` в `.env`. В `GET /api/health` поле `soffice` покажет, что найдено |
| Нет иллюстраций | не задан `GIGACHAT_AUTH_KEY`, либо `images.provider: none`, либо в брифе «Без картинок». `GET /api/health` → `images.enabled` |
| Ошибка GigaChat OAuth | ключ авторизации неверный или не совпадает область (`GIGACHAT_SCOPE`) |
| Иллюстрации идут медленно | личный тариф GigaChat не принимает параллельные запросы: одна картинка ≈ 20–50 с |
| `Нужен файл .pptx или .potx` | загрузка принимает только PowerPoint. `.ppt`, Keynote и Google Slides сначала сохраните как `.pptx` |
| `В шаблоне не найдено ни одного слайда, пригодного как холст` | шаблон пустой: в нём нет слайдов с заголовком и фоном. Загрузите шаблон с готовыми примерами слайдов |
| Шаблон разобран, но шрифты подменились | у шрифта нет кириллицы или он не найден: текст меряется запасным шрифтом рендерера. Положите шрифты в систему или используйте шаблон со встроенными шрифтами |
| Файл материалов не прочитан | `в файле нет текста (скан или пустой документ)` — сканы без текстового слоя не поддерживаются; формат вне txt, md, pdf, docx, pptx и других текстовых не читается |
| `Генерация прервана: сервер был перезапущен` | сервер перезапускали во время прогона. Запустите проект заново («Сгенерировать заново») |
| `генерация ещё идёт` (409) при удалении | дождитесь конца прогона |
| Прогресс обновляется рывками за прокси | отключите буферизацию SSE (`proxy_buffering off` в nginx) |
| Генерация упирается в 5 минут | уменьшите `llm.max_concurrency` при лимитах провайдера, отключите `pipeline.contextual_audit`, задайте `images.provider: none` |
| `npm ci` падает при сборке в Docker | так и задумано: lock-файл собран на Windows, поэтому `Dockerfile` разрешает зависимости заново по диапазонам `package.json` |
| Порт 8000 занят | смените порт в `docker-compose.yml` (`"8080:8000"`) или в аргументе `--port` |

Подробный журнал: `docker compose logs -f lekalo` или вывод `uvicorn`. Полный обмен с моделями по конкретному проекту — `data/jobs/<id>/llm_trace.jsonl`.

## 11. Ограничения

- **Проверено в LibreOffice, но не в PowerPoint.** Метрики текста считаются по реальным шрифтам шаблона. Если у шрифта нет кириллицы, измерение идёт по запасному шрифту рендерера, и в PowerPoint отрисовка может немного отличаться.
- **Цифры и факты берутся только из брифа.** Если данных мало, модель может обобщать. Такие места аудит помечает проверкой `facts_supported`, их можно исправить автоматически.
- **Растровые шаблоны восстанавливаются приближённо.** Переносятся фон, типографика, карточки и цвета. Логотипы и картинки исходника в новые колоды не попадают.
- **Иллюстрации генерируются по одной.** Личный тариф GigaChat не принимает параллельные запросы, поэтому на картинку уходит ~20–50 с.
- **Иллюстрации идут через хостинговый сервис.** Kandinsky вызывается через GigaChat API со своими условиями использования. Веса Kandinsky 3.x открыты (Apache 2.0), и генератор изолирован в `backend/app/layout/images.py`, но в этом прототипе они не развёрнуты локально. Подробности — в [docs/MODELS.md](docs/MODELS.md).
- **Соединение с GigaChat без проверки TLS-сертификата.** Проверка отключена только для этого хоста, потому что сертификаты Минцифры могут отсутствовать в системе. Если это неприемлемо, установите корневой сертификат и уберите `verify=False` в `backend/app/layout/images.py` либо отключите иллюстрации.
- **Нет аутентификации и разграничения доступа** между пользователями: проекты и шаблоны общие для всех, кто дошёл до сервиса.
- **Только десктоп.** Мобильные устройства и планшеты не целевые платформы.
