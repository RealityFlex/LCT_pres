# Архитектура

Пять слоёв. Каждый выдаёт явный артефакт (JSON на диске), поэтому любой шаг можно воспроизвести и проверить отдельно.

```
 .pptx ──► 1. Разбор шаблона ──► profile.json (дизайн-система, холсты, паттерны)
 бриф  ──► 2. Сценарий (LLM) ──► content.json (слайды, заголовки, тексты, данные)
            3. Три варианта + вёрстка ──► plan.json, layouts.json (IR) ──► PPTX
            4. Аудит (детерм. + VLM) ──► audit.json ──► выбранные исправления ──► пересборка
            5. Экспорт ──► PPTX (нативные объекты) · PDF · HTML
```

Главный принцип — **гибрид редактирования шаблона и композиции.** Структурные слайды (титул, раздел, финал) и собственные композиции шаблона клонируются из оригинала: текст пишется прямо в его фигуры, форматирование абзацев сохраняется. Остальные слайды раскладывает композер. Он работает на «холстах» — слайдах шаблона без контента, где остаются фон, логотипы, заголовок и колонтитулы — и берёт все размеры из токенов шаблона. Поэтому результат не выдаёт генерацию: он собран из материала самого шаблона.

## 1. Разбор шаблона — `backend/app/parsing/`

| Модуль | Что делает |
|---|---|
| `extract.py`, `ooxml.py` | Фигуры с абсолютными координатами (с учётом групп), наследование стилей run → lstStyle → макет → мастер, цвета темы и clrMap, заливки |
| `fonts.py` | Встроенные шрифты (EOT/обфусцированные) → TTF, подкачка из Google Fonts, инстансы вариативных шрифтов, метрики через FreeType. Шрифт без кириллицы меряется запасным шрифтом рендерера, отсутствующий жирный — с поправкой на синтетическое утолщение |
| `render.py` | LibreOffice headless с отдельным профилем на вызов → PDF → PNG. Шрифты шаблона регистрируются в сессии (Windows GDI / fontconfig). PyMuPDF — под общим замком: он не потокобезопасен |
| `analyze.py` | Для каждого слайда: заголовок, кикер, плашка заголовка; «хром» (фон, логотипы, колонтитулы, линейки, повторяющиеся элементы) против контента; служебные слайды (инструкции, палитры, библиотеки иконок); вид слайда (титул / раздел / план / контент / финал); **повторяющиеся группы** — карточки в подложках или, без подложек, наборы текстов одного стиля, выстроенные в ряд, колонку или полную сетку, вместе с иконками |
| `tokens.py` | Палитра (цвета, взвешенные по площади и объёму текста, роли фон / текст / основной / акценты / цвета диаграмм), типографика по ролям, шкала кеглей, сетка и шаг, стили карточек и таблиц |
| `canvases.py` | Холсты: слайд минус контент. По пикселям рендера уточняются свободная область, фон под слотами и ширина заголовка — логотипы бывают «вшиты» в картинку фона |
| `patterns.py` | **Паттерны шаблона.** Слайды-образцы с карточками, строками, крупными цифрами, таблицами, диаграммами или картинкой, пригодные для клонирования. Образец отбрасывается, если после заполнения на нём останется чужой контент: несколько скриншотов, декоративные рамки устройств, большие удаляемые тексты |
| `raster.py` | Шаблоны из слайдов-картинок (экспорт Figma/Canva). Гладкий фон восстанавливается аппроксимацией от рамки слайда. Находятся строки заголовков, их цвет и кегль, белые карточки и акценты. Из этого собирается редактируемый шаблон-заменитель и разбирается обычным путём |
| `vlm_labels.py` | VLM (скилл `template_analyst`) по контактному листу описывает стиль, тон и стиль иллюстраций. Детерминированный профиль остаётся первичным, модель только дополняет |
| `profile.py` | Оркестратор. Кэш по sha256 файла: повторная загрузка того же шаблона мгновенна |

Нарратив шаблона тоже извлекается: есть ли план и разделители, заглавные ли заголовки, есть ли кикеры, средняя длина заголовка, тип финала. Планировщик ему следует, аудит его учитывает: если шаблон пишет короткие заголовки-темы, «нет вывода в заголовке» — только совет.

## 2. Сценарий — `backend/app/planning/`, `backend/skills/`

`planner.py` вызывает скилл `deck_planner` (Qwen3.6-35B-A3B, JSON-режим с починкой ответа). Скилл получает:
- бриф;
- сюжетную арку под назначение (фича / продукт / проект / инициатива / обучение);
- формат повествования шаблона;
- ограничения шаблона: длину заголовка, наличие кикеров, число разделов.

Число слайдов выбирается по объёму брифа (11–14), если пользователь его не задал. Цифры и факты берутся только из брифа, а диаграммы строятся, только если в данных есть ряд чисел. Если текст не влез в макет, `text_condenser` сокращает его под лимит символов конкретного слота.

**Сверка с брифом до вёрстки** (`planning/facts.py`). Каждое число на слайдах — проценты, суммы, количества, сроки, годы — ищется в брифе. Исключения: нумерация («Шаг 2», «01») и очевидные производные в явном обороте («в 3 раза» при «с 4,5 до 1,5 ч»). Список `facts`, который возвращает сам планировщик, источником не считается. Слайды с неподтверждёнными числами до сборки отправляются корректору (`fixer`): он убирает число или заменяет его качественной формулировкой. Так «первые 4 склада» при плане в 12 или «Q3 2026» без дат в брифе не доходят до колоды.

Скиллы лежат в `backend/skills/<name>/<version>.yaml`. Активная версия задаётся в `config.yaml`, а в трассу каждого прогона пишутся имя, версия и хэш промпта. Промпты не правятся на месте: изменение — это новая версия файла (у `deck_planner` сейчас v1–v5; v5 — жёсткие правила фактов, запрет подписей-заглушек, план совпадает с разделами, деликатные темы).

## 3. Три варианта и вёрстка — `planning/variants.py`, `layout/`

### Три варианта

Одна контент-модель раскладывается тремя детерминированными стратегиями. Ось различий — **плотность × способ визуализации**. На этих двух параметрах пользователи чаще всего расходятся с автором шаблона, и они не требуют повторной генерации текста.

| | Стратегия | Что меняется |
|---|---|---|
| **A · Классический** | `faithful` | Максимум паттернов шаблона, баланс текста и визуала, основной холст шаблона |
| **B · Визуальный** | `visual` | Крупные цифры, диаграммы, иконки и иллюстрации; меньше текста; паттерны с числами и картинками |
| **C · Компактный** | `dense` | Слияние соседних слайдов, таблицы и сравнения вместо карточек, меньше слайдов |

`PatternPicker` оценивает пригодность каждого паттерна шаблона для слайда: вид, число пунктов, ёмкость слотов, наличие картинки. Он штрафует повторы и учитывает стратегию варианта. Если паттерн не подходит, слайд собирает композер по рецепту, всего их двенадцать:

- карточки, строки, процесс, таймлайн;
- крупные цифры, диаграмма с выводами, таблица, сравнение;
- ключевая мысль, картинка с текстом, план, разделитель.

### Вёрстка

- `recipes.py` (композер) раскладывает рецепт в контентной области холста с шагом сетки шаблона. Кегли берутся только из шкалы шаблона, текст подгоняется по реальным метрикам шрифта (`textfit.py`), цвета проверяются на контраст WCAG.
- `patterns.py` (заполнение паттернов) пишет текст в фигуры образца, снимает лишние пункты и равномерно раздвигает оставшиеся. Иконки образца он заменяет тематическими (Lucide) в цвете исходной, фото — сгенерированной иллюстрацией с обрезкой cover. Одинаковые роли соседних пунктов получают один кегль.
- `builder.py` собирает PPTX: клоны слайдов, нативные таблицы и диаграммы python-pptx в цветах палитры, иконки, картинки, заметки спикера. Затем удаляет исходные слайды шаблона.
- `images.py` генерирует иллюстрации: GigaChat → Kandinsky, стиль берётся из VLM-описания шаблона. Промпт очищается от «3D», чисел, кавычек и брендов в скобках — модель рисует их буквально. Результаты кэшируются по хэшу промпта.

Промежуточное представление (`layout/ir.py`: `SlideLayout`, `El`, `SlotFill`) отделяет решения вёрстки от OOXML. Исправления из аудита правят план или IR, после чего вариант пересобирается.

## 4. Аудит — `backend/app/audit/`

Подробности — в [AUDIT.md](AUDIT.md). Детерминированные проверки работают по файлу PPTX и пикселям рендера. Контекстные — VLM по картинке слайда и LLM по тексту колоды. Пользователь отмечает замечания, и `fixes.py` применяет исправления. Детерминированные исправления — кегль, сдвиг, цвет, удаление заглушки. Через LLM — заголовок-вывод, опечатки, неподтверждённые факты, сокращение текста. После этого изменённые слайды пересобираются и проверяются снова.

## 5. Экспорт и оркестрация

- **PPTX** — нативные объекты на макетах шаблона. **PDF** — LibreOffice. **HTML** — векторные SVG страниц во встроенном просмотрщике с навигацией клавишами и режимом показа.
- `pipeline.py` — асинхронная задача с событиями в SSE. Иллюстрации генерируются один раз на контент-модель. Три варианта собираются и рендерятся параллельно, контекстный аудит идёт параллельно по слайдам. Общий дедлайн — 300 с: при нехватке времени контекстный аудит усекается, колоды не теряются. Задача, прерванная перезапуском сервера, помечается ошибкой и перезапускается из интерфейса.
- `api/main.py` (FastAPI) отвечает за шаблоны, проекты, SSE-прогресс, превью, исправления, скачивание и каталог проверок. Он же раздаёт собранный фронтенд.

## Фронтенд — `frontend/`

React 19, Vite, Tailwind 4 с токенами VKUI (палитра VK), `@vkontakte/icons`, `vk-bridge`. В мини-приложении это даёт тему ВК, скачивание файлов и «поделиться».

**Экраны:**
- главная;
- мастер: шаблон → бриф → запуск;
- живой прогресс: этапы, сценарий, заготовки вариантов;
- проект: вкладки A/B/C, лента слайдов, просмотр, аудит с подсветкой зон и выбором исправлений, сравнение вариантов, показ, экспорт;
- библиотека шаблонов с разобранной дизайн-системой;
- «Система»: модели, скиллы, каталог проверок.

Вёрстка адаптивная: на десктопе боковая панель, на телефоне нижняя навигация и нижние листы.
